## 四、协作规范

### 分支策略

```
main          ← 随时可演示的稳定版本
└── dev       ← 日常集成
    ├── feat/web-dashboard
    ├── feat/server-gateway
    └── feat/vision-detect
```

- 功能开发走 `feat/*` 分支，完成后合并到 `dev`
- 每周日晚 `dev` 合并到 `main`，打 tag（如 `v0.1-w1`）
- `main` 分支必须保证能跑

### 提交规范

**所有提交信息使用中文**，格式：

```
<类型>: <简短描述>

<可选：详细说明>
```

类型：`新增` / `修复` / `重构` / `文档` / `样式` / `测试`

示例：
```
新增: 温度双环组件
修复: 断线重连后曲线数据重复
文档: 补充 W2 验收标准
```

### 每日站会（10 分钟）

1. 昨天做了什么
2. 今天要做什么
3. 有什么阻塞

### 接口先行

跨模块接口（前后端字段、API 路径）必须先写进 `docs/接口约定.md` 再动工，避免后期返工。

## 五、验收清单

### 功能验收

- [ ] 手机能实时看到温度、进度、摄像头画面
- [ ] 手机能上传 G-code 并启动打印
- [ ] 暂停、恢复、急停全部生效
- [ ] 断料时自动暂停并弹窗告警
- [ ] 超温时强制关闭加热
- [ ] 视觉检测能识别遮挡并告警
- [ ] 电脑端大屏显示正常
- [ ] 参数配置能读取、修改、保存、回滚
- [ ] exe 能双击运行
- [ ] 演示模式可一键切换

### 性能验收

- [ ] 状态推送延迟 < 1 秒
- [ ] 控制响应 < 500 毫秒
- [ ] 启动到首屏 < 3 秒
- [ ] 摄像头延迟 < 2 秒
- [ ] 断料响应 < 2 秒
- [ ] 连续运行 72 小时不崩

### 答辩验收

- [ ] 备播视频已录制
- [ ] 断网演练通过
- [ ] 1 小时讲稿熟练
- [ ] 三层差异化表述能脱稿讲
- [ ] 三个失败故事能讲清楚
