## 1. 项目概述

### 1.1 项目背景

本项目基于 MakerWorld 开源模型「笨大鱼的 DIY 自制 3D 打印机 —— 云雀 V1.06」完成整机装配，并在此基础上**自主开发一套覆盖手机端与电脑端的控制软件**。

当前消费级 3D 打印机普遍存在三个问题：

1. **操作必须站在机器旁边**——切片、拷卡、插卡、按旋钮，长任务期间无法离开；
2. **过程不可见**——打印中出问题（断料、翘边、炒面）只能等几小时后回来发现废件；
3. **数据不沉淀**——每次打印的温度、速度、耗时都是黑盒，无法复盘。

本软件要做的，是把一台「需要人守着」的打印机，变成一台「**可以在手机上看、在电脑上管、出了问题会喊人**」的智能设备。

### 1.2 项目定位

| 维度 | 内容 |
|---|---|
| 硬件基础 | 开源社区方案二次开发（CoreXY 结构 + SKR 主板） |
| 软件定位 | **自主实现**，不依赖任何第三方云服务 |
| 网络环境 | 仅局域网，**全程不出内网** |
| 目标用户 | 学校创客空间、个人创客、小型工作室 |

### 1.3 核心卖点（按主次排序）

1. **软硬一体闭环**——从切片文件到手机监控到故障告警，全链路自研打通；
2. **AI 视觉辅助**——基于传统图像算法的炒面/首层异常检测，轻量、可解释、本地运行；
3. **低成本可复制**——整套软件零授权费，老旧安卓设备即可充当触屏终端。

## 2. 术语与缩写

| 术语 | 说明 |
|---|---|
| Klipper | 开源 3D 打印机固件，由上位机承担运动规划，下位机只做执行 |
| Moonraker | Klipper 的 Web API 服务层，提供 HTTP 与 WebSocket 接口 |
| JSON-RPC | Moonraker 使用的远程调用协议，支持订阅式状态推送 |
| MJPEG | 动态 JPEG 视频流，适合低带宽局域网传输 |
| G-code | 3D 打印指令集，由切片软件生成 |
| PWA | 渐进式 Web 应用，可添加到手机桌面 |
| 炒面 | 打印失败时喷头裹着耗材形成团状废料的俗称 |

## 3. 用户角色与场景

### 3.1 角色定义

| 角色 | 描述 | 主要设备 |
|---|---|---|
| 操作者 | 发起打印、监控过程、处理异常的学生/创客 | 手机 |
| 管理者 | 查看全局状态、配置参数、导出数据 | 电脑 |
| 现场观众 | 答辩现场观看演示 | 投影大屏 |

### 3.2 典型场景

**场景 A：远程监控（最高频）**
小林在教室上课，打印机在创客空间打印一个 4 小时的模型。他打开手机，看到进度 62%、喷头 210℃、剩余 1 小时 27 分，摄像头画面里喷嘴正常出料。他锁屏继续上课。

**场景 B：异常告警**
打印到 78% 时耗材用完，断料开关触发。手机弹出红色告警并响铃，小林点进去看到「断料检测触发，打印已暂停」，换上耗材后点「继续打印」。

**场景 C：视觉检测**
首层打印时摄像头定时抓图，算法发现喷嘴周围出现团状物（炒面），自动暂停并推送告警。

**场景 D：电脑端管理**
答辩现场，电脑大屏显示摄像头画面、温度曲线、实时日志。讲解时指着曲线说明「升温斜率稳定，PID 调参有效」。

**场景 E：离线兜底**
现场网络异常，一键切换到「演示模式」，界面用内置模拟数据继续运行，讲解不中断。

## 4. 系统架构

### 4.1 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│  展示层（Presentation）                                        │
│  ┌────────────┐  ┌────────────┐  ┌──────────────┐            │
│  │ 手机端 H5   │  │ 电脑端 exe  │  │ 红米2 触屏    │            │
│  │ (PWA/apk)  │  │ (Electron) │  │ (浏览器全屏)  │            │
│  └────────────┘  └────────────┘  └──────────────┘            │
└─────────────────────────┬────────────────────────────────────┘
                          │ WebSocket (JSON-RPC) + HTTP
┌─────────────────────────▼────────────────────────────────────┐
│  应用网关层（FastAPI，运行于笔记本）                            │
│  · 状态聚合与缓存     · 告警规则引擎                          │
│  · 延时抓图任务       · 视觉检测（OpenCV）                     │
│  · SQLite 曲线存储    · 文件管理                              │
└─────────────────────────┬────────────────────────────────────┘
                          │ Moonraker HTTP / WebSocket
┌─────────────────────────▼────────────────────────────────────┐
│  设备控制层（Klipper + Moonraker）                             │
│  主：笔记本　备：红米2（Termux + Debian chroot）               │
└─────────────────────────┬────────────────────────────────────┘
                          │ USB 串口
┌─────────────────────────▼────────────────────────────────────┐
│  执行层（BIGTREETECH SKR 主板 + CoreXY 机械结构）              │
│  · 步进电机 ×4  · 加热棒 ×2  · 热敏电阻 ×2  · 断料开关        │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 架构设计说明

**为什么分三层？**

传统方案把 Klipper 直接塞进老手机，1GB 内存跑 Python 服务极易 OOM（内存溢出）。本项目把职责拆开：

- **设备控制层**只做实时性要求最高的事（运动规划、温度 PID），跑在性能更有保障的设备上；
- **应用网关层**承担所有业务逻辑（告警判断、图像处理、数据存储），算力需求集中在这里；
- **展示层**是纯前端，任何有浏览器的设备都能接入，包括 1GB 内存的红米2。

这样带来的直接好处：**红米2 即使性能不足，也只影响它自己那一块屏幕，不会拖垮整台打印机**。

**降级策略（双冗余）**

| 场景 | 主方案 | 备方案 |
|---|---|---|
| 控制主机 | 笔记本跑 Klipper | 红米2 跑 Klipper（Termux） |
| 网络 | 自带路由器组网 | 手机热点 / 直连网线 |
| 演示 | 真机实时数据 | 演示模式（模拟数据） |

### 4.3 通信协议

| 用途 | 协议 | 说明 |
|---|---|---|
| 状态推送 | WebSocket + JSON-RPC | 订阅 `printer.objects.subscribe`，温度/进度/坐标秒级推送 |
| 控制指令 | HTTP POST | `printer.gcode.script`、`printer.print.pause` 等 |
| 文件传输 | HTTP multipart | `server.files.upload` |
| 视频流 | HTTP MJPEG | `/webcam/?action=stream` |

### 5.2 详细需求

#### F-01 实时状态仪表盘【P0】

**描述**：以仪表盘形式展示打印机当前运行状态。

**展示内容**：
- 喷头温度：当前值 / 目标值，环形仪表 + 实时曲线
- 热床温度：当前值 / 目标值，环形仪表 + 实时曲线
- 打印进度：百分比环形进度条
- 已用时间 / 剩余时间
- 当前坐标 X / Y / Z
- 打印速度倍率（M220）
- 挤出倍率（M221）
- 当前文件名
- 连接状态指示

**验收标准**：
1. 状态数据刷新间隔 ≤ 1 秒；
2. 温度曲线保留最近 5 分钟数据，支持悬停查看具体数值；
3. 断连时顶部显示红色提示条，并自动重连（重试间隔 3 秒，最多 10 次）；
4. 断连期间界面保留最后一次已知状态，标注「数据已过期」。

---

#### F-02 摄像头实时画面【P0】

**描述**：展示打印机舱内摄像头画面。

**需求**：
- MJPEG 流实时播放，延迟 < 2 秒；
- 支持全屏查看（手机横屏、电脑独立窗口）；
- 支持手动抓拍，快照保存至 `screenshots/` 目录；
- 画面异常（摄像头离线）时显示占位图与提示。

**验收标准**：在局域网环境下，画面连续播放 30 分钟不断流。

---

#### F-03 打印控制【P0】

**描述**：对当前打印任务进行控制。

**功能项**：
| 操作 | 指令 | 保护措施 |
|---|---|---|
| 暂停 | `printer.print.pause` | 直接执行 |
| 恢复 | `printer.print.resume` | 直接执行 |
| 急停 | `printer.emergency_stop` | **红色按钮，任何页面置顶可见** |
| 取消打印 | `printer.print.cancel` | 二次确认弹窗 |

**安全要求**：
1. 急停按钮在所有页面固定悬浮，点击一次立即生效，不需要确认（避免延误）；
2. 急停触发后界面进入「已急停」状态，需手动点击「解除」才能继续操作；
3. 取消打印必须二次确认，弹窗中显示当前进度与已耗时。

---

#### F-04 温度与进给手动控制【P0】

**功能项**：
- 喷头目标温度设置（0–300℃，快捷按钮：预热 PLA 200℃ / PETG 240℃ / ABS 260℃ / 关闭）
- 热床目标温度设置（0–120℃，快捷按钮：PLA 60℃ / PETG 80℃ / ABS 100℃ / 关闭）
- 挤出 / 回抽（步长可选 5mm / 10mm / 50mm）
- 打印速度倍率调节（50%–200%）
- 挤出倍率调节（80%–120%）

**安全要求**：
1. 设置温度超过 300℃ 时拒绝执行并提示；
2. 加热时显示倒计时与当前温度；
3. 温度上限保护：软件层监测，超过阈值（默认喷头 290℃ / 热床 110℃）强制发送关闭加热指令。

---

#### F-05 G-code 上传与管理【P0】

**功能项**：
- 从本机选择 `.gcode` 文件上传至打印机存储；
- 文件列表展示：文件名、大小、预计打印时间、耗材用量、缩略图；
- 操作：开始打印、删除、重命名、下载到本地；
- 上传进度条，支持大文件（>100MB）分块传输；
- 上传中断支持续传或重试。

**验收标准**：
1. 100MB 文件在局域网内上传耗时 < 60 秒；
2. 上传完成后自动解析元数据（预计时间、耗材长度）并展示；
3. 文件名含中文时正常显示，不乱码。

---

#### F-06 故障告警【P0】

**告警类型**：

| 类型 | 触发条件 | 级别 | 处理动作 |
|---|---|---|---|
| 断料 | 断料开关信号变化 | 严重 | 暂停打印 + 弹窗 + 响铃 |
| 超温 | 实测温度 > 阈值 | 严重 | 强制关闭加热 + 弹窗 |
| 温度异常 | 加热 60 秒内温升 < 2℃ | 警告 | 弹窗提示 |
| 打印失联 | WebSocket 断开 > 10 秒 | 警告 | 顶部红条 + 自动重连 |
| 打印完成 | 进度到达 100% | 通知 | 弹窗 + 语音播报 |
| 视觉异常 | 图像检测命中 | 严重 | 暂停打印 + 弹窗 + 保存截图 |

**告警交互要求**：
1. 手机端：全屏弹窗 + 震动 + 提示音；
2. 电脑端：弹窗 + 顶部横幅 + 声音；
3. 告警历史在本次会话内可查看（最近 50 条）；
4. 严重告警需用户点击「我已知晓」才消失。

---

#### F-07 延时抓图【P0】

**描述**：打印过程中定时抓拍，为后续延时视频提供素材。

**需求**：
- 抓图间隔可配置（默认每 10 秒，或每层一次）；
- 图片按任务分目录保存：`screenshots/{任务名}/{时间戳}.jpg`；
- 单任务最多保存 2000 张，超出后自动降低采样频率；
- 打印结束后可打包下载全部图片；
- **本版本不实现视频合成**，合成在电脑端用 ffmpeg 完成（答辩时现场演示）。

**存储要求**：图片保存在网关所在机器，不占用红米2 存储。

---

#### F-08 演示模式【P0】

**描述**：不连接真实打印机也能展示完整功能，用于现场兜底。

**需求**：
- 通过页面角落按钮或快捷键（`Ctrl+Shift+D`）切换；
- 切换后使用内置模拟数据源：
  - 温度曲线按正弦扰动模拟真实波动；
  - 打印进度按时间线性推进；
  - 摄像头使用预录视频循环播放；
  - 告警可按预设时间点触发（用于演示告警流程）；
- 界面明显标注「演示模式」水印，避免误导评委；
- 切换回真实模式无需刷新页面。

---

#### F-09 虚拟摇杆 XYZ 移动【P1】

**描述**：在手机和电脑上通过摇杆或方向键控制打印头移动。

**需求**：
- 三轴独立控制，也可切换 XY 平面联合控制；
- 步距可选：0.1mm / 1mm / 10mm；
- 移动速度可调（默认 3000mm/min）；
- 实时显示当前坐标；
- **软限位保护**：读取打印机的 `position_max` 配置，接近边界时禁止继续移动并提示；
- 必须先回零（Homing）才能使用，未回零时按钮禁用。

**安全要求**：按住移动、松手停止（避免一直移动撞机）。

---

#### F-10 3D 模型预览【P1】

**描述**：在上传前预览待打印模型。

**需求**：
- 支持 `.stl` 与 `.3mf` 格式；
- Three.js 渲染，支持旋转、缩放、平移；
- 自动居中，按模型尺寸调整视角；
- 显示模型包围盒尺寸（mm）与三角面数；
- 手机端支持双指缩放、单指旋转。

**技术要点**：STL 解析在浏览器端完成，不占用服务器算力。

---

#### F-11 扫码连接【P1】

**描述**：通过扫描二维码快速接入打印机。

**需求**：
- 系统生成包含网关地址的二维码（如 `http://192.168.1.100:8000`）；
- 手机扫码后自动跳转并连接，无需手动输入 IP；
- 二维码在电脑端「连接设置」页展示，可打印张贴在机器上。

---

#### F-12 打印完成通知与语音播报【P1】

**需求**：
- 打印完成时，手机、电脑同时弹窗；
- 使用浏览器 Web Speech API 播报「打印已完成，耗时 X 小时 X 分」；
- 播报可开关，默认开启。

---

#### F-13 耗材余量估算【P1】

**需求**：
- 从 G-code 元数据读取耗材总长度（mm）与重量（g）；
- 用户可设置当前耗材卷初始重量（默认 1000g / 常用 250g 小卷）；
- 打印中实时扣减，显示剩余百分比与预估可打印长度；
- 余量低于 10% 时给出黄色提示。

---

#### F-14 参数配置页【P1】

**描述**：可视化编辑 Klipper 配置参数。

**需求**：
- 展示当前 `printer.cfg` 关键参数（限位、最大速度、加速度、PID 参数）；
- 支持修改常用项（最大速度、加速度、回零速度）；
- **保存前三步保护**：
  1. 语法校验（Klipper 提供 `config.check` 接口）；
  2. 校验失败时显示错误行号，禁止保存；
  3. 保存后自动备份原配置为 `printer.cfg.bak.{时间戳}`，重启失败自动回滚并提示。

---

#### F-15 配置包导出【P1】

**需求**：
- 一键导出 zip 包，包含：`printer.cfg`、`macros.cfg`、`moonraker.conf`；
- 文件名格式：`云雀配置_{日期}.zip`；
- 同时支持导入（用于换机恢复）。

---

#### F-16 G-code 逐层预览【P2】

**需求**：解析 G-code 文件，按层渲染路径，支持拖动查看任意层。**仅电脑端**，作为技术深度展示项。

#### F-17 打印报告导出【P2】

**需求**：每次打印结束后生成一页报告（模型缩略图、耗时、耗材、温度曲线图、结果判定），导出为 PDF。

### 7.4 视觉检测算法方案

**算法选择：帧差法 + 区域阈值**

1. **基准帧建立**：打印开始后第 5 分钟，抓取一张无遮挡的理想画面作为基准；
2. **分区**：将画面划分为 3×3 网格，重点检测喷嘴区域（中心格）；
3. **帧差计算**：每 10 秒抓图，与基准帧做差分，得到变化像素；
4. **阈值判定**：
   - 变化像素占比 > 阈值 T1（默认 35%）→ 疑似异常；
   - 连续 2 次判定为异常 → 触发告警；
5. **排除干扰**：排除打印头正常移动造成的变化（通过 G-code 位置信息预估喷头区域，将该区域掩膜）；
6. **输出**：保存异常帧截图，推送告警。

**为什么不用深度学习？**
- 红米2/笔记本 GPU 算力有限，YOLO 类模型推理占用大；
- 缺少真实失败样本，无法有效训练；
- 帧差法**原理可向评委完整解释**，体现工程思维而非调包。

**局限性与后续改进方向**（答辩时必须主动说明）：
- 光照变化、模型颜色差异会造成误报；
- 后续可引入轻量模型（MobileNet 蒸馏）提升泛化能力；
- 当前版本定位为「辅助提醒」，不替代人工巡检。

## 11. 答辩要点

### 11.1 差异化表述（针对「和网上开源有什么区别」）

**第一层：定位差异**
> OctoPrint 是通用型远程打印插件，面向有经验的玩家；我们做的是**面向教学场景的软硬一体方案**，从开机到打印只需三步。

**第二层：架构差异**
> OctoPrint 是单体架构，所有逻辑跑在树莓派上；我们做了**三层分离**，业务逻辑与实时控制解耦，老旧设备也能当终端用。

**第三层：能力差异**
> 我们在通用方案基础上增加了**本地视觉检测**和**断料联动暂停**，这是原方案没有的。

### 11.2 主动说明的局限

答辩时主动讲局限比被问出来更好：

- 视觉检测目前是传统算法，泛化能力有限，未来计划引入轻量模型；
- 红米2 性能有限，我们通过架构分层规避了这个问题；
- 目前是单机版本，多机管理在路线图中。

### 11.3 失败故事（3 个真实技术难点）

**故事一：红米2 跑不动 Klipper**
最初想把 Klipper 直接装在红米2 上，结果 1GB 内存一跑 Python 服务就 OOM。最后改成三层架构，把业务逻辑拆到笔记本上，红米2 只做显示终端。**收获**：性能不足不该硬扛，应该改架构。

**故事二：摄像头画面延迟 8 秒**
最初用 HTTP 轮询抓图再推给前端，延迟高达 8 秒。改成 Moonraker 原生 MJPEG 流后降到 1 秒内。**收获**：不要重复造轮子，先看底层能提供什么。

**故事三：配置改错导致 Klipper 起不来**
调参数时手滑改错 `printer.cfg`，重启后服务直接崩，现场演示一度中断。后来加了「保存前校验 + 自动备份 + 失败回滚」三步保护。**收获**：任何能改坏系统的操作，都要有回滚路径。
